# はじめての端末間共有ガイド

**Windows、Chromebook、Android、iPadで、同じタスクを見るための手順です。**

設定作業は最初にパソコンで一度行います。途中で必要になるものは、GitHubのこのリポジトリ、Web公開用のNetlifyアカウント、データ保存用のSupabaseアカウント、確認メールを受け取れるメールアドレスです。各サービスの料金・利用上限は登録前に確認してください。

## 先に知っておくこと

| 名前                 | 何のために使うか                                     |
| -------------------- | ---------------------------------------------------- |
| GitHub（このページ） | アプリのファイルと説明書の保管場所                   |
| 公開URL（Netlify）   | どの端末でも同じアプリを開くための住所               |
| Supabase             | タスク・チェックリスト・画像を端末間で同期する保存先 |
| アプリ用アカウント   | Tasklyにログインするためのメールアドレスとパスワード |

**GitHubからZIPをダウンロードするだけでは、端末間の自動共有は始まりません。** 以下の「アプリの公開」と「同期先の接続」を両方行います。

この機能は**自分の複数端末で同じアカウントを使う**ためのものです。人を招待するチーム機能や、異なるアカウント同士の共有機能はありません。アプリ用パスワードを他人へ渡さないでください。

## 0. すでにタスクを使っている場合

1. 今使っているTasklyの「設定・データ同期」を開きます。
2. 「バックアップ」の「書き出す」を押し、JSONファイルを保存します。
3. このあと作る公開URLと、今までの `localhost` は保存場所が別です。公開後、まず1台目でこのJSONを「読み込む」ことで引き継げます。

ブラウザーのデータを消す前には、必ず書き出してください。

## 1. アプリのファイルをダウンロードする

1. [taskmakerのトップページ](https://github.com/fuj4022-code/taskmaker)を開きます。
2. 緑の **Code → Download ZIP** を押します。
3. ダウンロードしたZIPを展開します。WindowsはZIPを右クリックして **すべて展開** です。
4. 展開されたフォルダーの中に `index.html`、`src`、`public`、`sw.js`、`manifest.webmanifest` があることを確認します。

**Web公開だけならNode.jsのインストールは不要です。** `START-WINDOWS.cmd` は自分のWindowsだけで試すための起動方法です。

## 2. 共通の公開URLを作る

ここでは、ファイルをドラッグして公開できるNetlifyを使います。別の静的Webホストでも、HTTPSかつサイトのルートに配置できるサービスなら利用できます。

1. パソコンで新しいフォルダー「Taskly公開用」を作ります。
2. 展開したフォルダーから、次の**5つ**をその中へコピーします。`src` と `public` はフォルダーごとコピーしてください。

   ```text
   Taskly公開用/
   ├─ index.html
   ├─ src/
   ├─ public/
   ├─ sw.js
   └─ manifest.webmanifest
   ```

3. [Netlify](https://app.netlify.com/)に自分のアカウントでログインします。
4. 手動デプロイ（**Deploy manually**、フォルダーをドラッグ＆ドロップする方法）を選びます。[Netlify Drop](https://app.netlify.com/drop)からも進められます。
5. 「Taskly公開用」をフォルダーごとアップロードします。`index.html` が公開先の一番上になるようにしてください。
6. 発行された `https://……netlify.app` のURLを開き、Tasklyが表示されることを確認します。
7. **このURLをメモしておきます。以後、すべての端末でこの同じURLを開きます。**

アプリの画面自体は公開されますが、タスクは各ブラウザー、または次に設定する認証付きSupabaseに保存されます。アカウント情報・バックアップJSON・秘密のキーを公開用フォルダーへ入れないでください。

機能が追加された後は、すべての端末をオンラインにして一度再読み込みし、最新版で使ってください。

今後アプリを更新するときは、新しいファイルを**同じNetlifyプロジェクト**へ再デプロイします。毎回別のサイトを作るとURLが変わり、端末内の保存場所も変わります。更新前にバックアップしておくと安心です。

> GitHub Pagesの標準的な `/taskmaker/` 配下への配置には、現在のアプリは対応していません。このガイドではサイトのルートで公開する方法を使います。

## 3. Supabaseに保存先を作る

1. [Supabase](https://supabase.com/dashboard)に登録・ログインします。これはTasklyのログインとは別の、保存先を管理するアカウントです。
2. **New project** からプロジェクトを作成します。プロジェクト名は `taskly` などで構いません。データベース用の強いパスワードを設定し、準備が終わるまで待ちます。
3. Supabaseの **SQL Editor** を開き、新しいクエリを作成します。
4. GitHubの [`supabase.sql`](../supabase.sql) を開きます。ファイル右上のコピー操作、または **Raw** の画面でSQLを全部コピーします。
5. SQL Editorへ貼り付けて **Run** を押します。エラーがなく完了することを確認します。

このSQLが、タスクを保存する `taskly_documents` という表と、**ログインした本人だけが自分のデータを読み書きできるルール（RLS）**を作ります。SQLの実行を省略しないでください。以前のTasklyからの更新なら同じ表をそのまま使え、今回の機能追加のためのSQL変更は不要です。

## 4. 接続に使うURLと公開用キーを確認する

Supabaseのプロジェクト画面で、接続情報や設定の **Project URL** と **API Keys** を探します。画面の版によって **Connect**、**Project Settings**、**Data API** などに分かれています。

必要なのは次の2つです。

| Tasklyに入力する欄         | Supabaseでコピーするもの                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------ |
| Project URL                | `https://……supabase.co` のURL                                                                    |
| Publishable key / anon key | **Publishable key**（`sb_publishable_`で始まる公開用キー）、または旧形式の **anon / public key** |

**Secret key（`sb_secret_`）やservice_roleキーは使わないでください。** データベースのパスワードもここには入力しません。公開用キーを使っても、手順3のRLSとユーザー認証でデータは保護されます。

URL・公開用キーをGitHubのファイルへ書き込む必要はありません。後でTasklyの設定画面に入力します。

## 5. アプリ用のログインを有効にする

1. Supabaseの **Authentication** にあるログイン方法の設定（**Sign In / Providers** や **Providers**）を開きます。
2. **Email / Password** を有効にします。自分のアカウントを作る間は新規登録も許可します。
3. **URL Configuration** の **Site URL** を、手順2で作ったTasklyの公開URLにします。メール確認後に戻るための設定です。必要なら同じURLを許可するRedirect URLsにも追加します。
4. メール確認を使う場合は **Confirm email** を有効にしたままにします。

## 6. 1台目でTasklyを接続する

1. 公開URLでTasklyを開きます。
2. 「設定・データ同期」を押します。小さい画面なら、左上のメニューボタンから開けます。
3. 手順4の **Project URL** と **公開用キー** を貼り付け、**接続設定を保存** を押します。
4. 自分のメールアドレスと、Taskly用のパスワード（8文字以上）を入力し、**アカウントを作成** を押します。
5. 届いた確認メールのリンクを開きます。その後、Tasklyの「設定・データ同期」で同じメール・パスワードを入力し、**ログイン** します。すでにTasklyアカウントを作ってあれば、作り直す必要はありません。
6. 手順0でバックアップを作った方は、この公開URLのTasklyで **読み込む** を押し、JSONファイルを選びます。
7. **今すぐ同期** を押します。「すべての端末と同期しました」と表示されれば接続成功です。

確認メールが届かないときは迷惑メールフォルダーも見てください。Supabaseのメール送信上限やプロジェクトの利用状態によって待ち時間が必要な場合があります。

## 7. 2台目以降のOSで開く

どのOSも、アプリ用アカウントを新規作成せず、**1台目と同じアカウントでログイン**します。

| 端末       | 開き方・アプリとして置く方法                                                                                                                         |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Windows    | EdgeまたはChromeで同じ公開URLを開く。ブラウザーの「アプリをインストール」から追加できます。                                                          |
| Chromebook | Chromeで同じ公開URLを開く。「アプリをインストール」から追加できます。                                                                                |
| Android    | Chromeで同じ公開URLを開く。メニューの「アプリをインストール」または「ホーム画面に追加」を選びます。                                                  |
| iPad       | Safariで同じ公開URLを開く。「共有」→「ホーム画面に追加」を選びます。追加したアイコンから使う場合は、そちらでも接続設定・ログインを確認してください。 |

各端末で「設定・データ同期」に**同じProject URL・同じ公開用キー**を保存し、**同じメールアドレス・パスワード**でログインします。**今すぐ同期** を押してください。

### 共有できたか確認する

1. 1台目で「共有テスト」というタスクを1つ作り、保存します。
2. 1台目で「今すぐ同期」を押し、成功表示を待ちます。
3. 2台目でも「今すぐ同期」を押します。「共有テスト」が表示されれば成功です。
4. 2台目でそのタスクを「完了」にして同期します。1台目でも同期し、状態が変わるか確認します。

チェックリストの期間、進行度、画像、列名、アーカイブも同期対象です。ガントの表示期間・日／週の単位・列幅とサイドバーの開閉は、端末ごとの見やすさに合わせる設定なので、そのブラウザーだけに保存します。

## 8. オフラインで使う

1. 使う端末で一度オンラインのままTasklyを開き、少し待ってから再読み込みします。
2. Wi-Fiを切る、または機内モードにしてからアプリを開き直し、表示されるか試します。
3. タスク・チェックリスト・期間・画像などを編集し、保存できます。
4. ネットが戻ると、ログイン済みなら変更後・オンライン復帰・画面復帰・約1分ごとに同期します。すぐ反映したいときは「今すぐ同期」を押してください。

初回の読み込みや、まだログインしていない端末の接続設定にはインターネットが必要です。即時のリアルタイム共同編集ではありません。同じタスクを2台で同時に編集すると、更新日時が新しい方を採用します。端末の時計は自動設定にしてください。

## 困ったとき

| 困ったこと                                    | 確認すること                                                                                                                  |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| ほかの端末でタスクが出ない                    | 同じ公開URL・Supabase Project URL・メールアドレスか確認し、両方で同期成功を待ちます。アーカイブや検索の絞り込みも確認します。 |
| `localhost:5173` がスマホで開かない           | `localhost` は今使っている端末自身を指します。スマホやiPadでは手順2のHTTPS公開URLを使います。                                 |
| 表が見つからない、`taskly_documents` のエラー | 手順3のSQLを、接続先と同じSupabaseプロジェクトで実行したか確認します。                                                        |
| ログインできない                              | 確認メールを開いたか、アプリ用のメール・パスワードか確認します。Supabase管理画面用のログインとは別です。                      |
| 同期だけできない                              | 通信状態、公開用キー、Supabaseプロジェクトの稼働状態・上限、SQL実行を確認します。端末内のデータは書き出して保管できます。     |
| iPadでオフライン起動できない                  | HTTPSの同じURLをオンラインで一度読み込んだか確認します。プライベートブラウズを避け、ホーム画面のアイコン側でも確認します。    |
| タスクが消えたように見える                    | タグ、状態、検索、アーカイブを確認します。別URL・別ブラウザーには端末内データが引き継がれません。                             |
| アプリを更新したのに古い画面                  | オンラインで開き直し、再読み込みします。サイトデータの削除は最後の手段とし、その前にバックアップしてください。                |

ログアウトしても端末内のタスクは残ります。共有端末を使う場合は、バックアップと同期を確認してからブラウザーのサイトデータを削除してください。画像もブラウザーに保存するため、定期的なJSONバックアップをおすすめします。
