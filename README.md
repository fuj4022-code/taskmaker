# Taskly — 自分らしく、進めよう

かんばん・ガントチャート・月カレンダーで使う、日本語のタスク管理アプリです。Windows・Chromebook・Android・iPadのモダンブラウザーで利用できます。端末内だけでも動作し、自分のSupabaseプロジェクトを接続すると同じアカウントで端末間共有できます。

## Windows・Chromebook・Android・iPadで同じタスクを使いたい方へ

**[初心者向け・端末間共有ガイド](docs/SHARING.md)** に、ZIPのダウンロード、Web公開、Supabase設定、各OSでのログイン、つながらないときの確認方法を画面の操作順にまとめました。

## 起動

Node.js 20以上（検証環境は24）で、リポジトリ内から実行します。

```sh
npm ci
npm run dev
```

ポートは5173です。`PORT=3000 npm start` で変更できます。Windowsでは `START-WINDOWS.cmd` でも起動できます。アプリ本体は外部ライブラリーに依存せず、ビルドも不要です。npmの依存関係はテスト専用です。

## 使い方

- 「タスクを追加」からタスク名、プロジェクト、開始日・期限日、メモを入力します。詳細の変更は「変更を保存」で確定します。
- タグは入力してEnterまたは「追加」で複数付けられます。画面上部でタグ・状態・キーワードによる絞り込みができます。
- カード右上の状態ボタンを押すたびに **未着手 → 進行中 → 完了 → 未着手** と切り替わります。詳細画面では各状態を直接選べます。PCではカードを別の列へドラッグしても変更できます。
- タスク詳細にチェックリストを作成でき、項目の追加・編集・削除・完了が可能です。カードに達成数と進捗を表示します。各チェック項目に開始日・期限日も設定でき、ガントではタスクの下に表示されます。
- ガントチャートは35日間を表示します。左右の矢印で期間移動し、「今日」で戻れます。帯の両端をドラッグして開始日・期限日を変更できます。端のボタンにフォーカスして左右キーでも1日ずつ調整でき、タッチ操作にも対応します。「1日の幅」スライダーで日付の横幅を調整できます。バーやタスク名を押して詳細から日程を編集する方法も使えます。開始日のみ／期限日のみならその日を表示し、日程なしのタスクも一覧に残ります。
- 「カレンダー」では月単位で予定を確認できます。期間中の各日にタスクを表示し、タスクを押すと詳細が開きます。日付の「＋」でその日のタスクを作成できます。日程なしのタスクは下の一覧に残ります。
- 進行度は状態とは別に「順調・遅れ気味・先行」から設定し、カード・ガント・カレンダーに表示します。
- かんばんの列見出し横の鉛筆で列名を変更できます。列名は全プロジェクトで共通です。プロジェクトを選んだ後、画面タイトル横の鉛筆からプロジェクト名も変更できます。
- 完了したカードのアーカイブボタンで保管でき、通常のかんばん・ガント・カレンダーから非表示になります。左の「アーカイブ」で確認・復元できます。削除とは別なので、チェックリストや画像は残ります。
- 左上のメニューボタンでサイドバーを開閉できます。PCでは閉じると表示領域が広がります。ガントの幅とPCの開閉状態はブラウザーごとに保存します。
- 画像はJPEG・PNG・WebP、各10MB以下、最大8枚まで。長辺1400px以下のJPEGに圧縮して保存します。画像名を押すと保存できます。
- サイドバーの「新しいプロジェクト」から分類を追加できます。初期データはサンプルで、タスク詳細から削除できます。
- スマートフォンではかんばんを横にスワイプして各列へ移動します。ガントも表の内側を横スクロールできます。

タスクはIndexedDBに保存されます。保存に失敗したときはエラーを表示し、編集内容を残します。「設定・データ同期」から画像・チェックリストを含むJSONバックアップを書き出せます。読み込みは最新の更新を採用して統合します。ブラウザーの保存データ削除・シークレットモード・OSによる保存領域解放には注意し、定期的にバックアップしてください。保存データの保持リクエストも設定画面から行えます。

## オフライン・各端末へのインストール

同じHTTPSの公開URLを各端末で開いてください。初回オンライン表示でService Workerがアプリのファイルを保存した後は、オフラインで再起動・タスク編集・画像添付ができます。オンライン復帰後、ログイン済みなら自動同期します。別のURL・ブラウザーの端末内データは独立しています。

Chromeの「アプリをインストール」またはiPadのSafariの「共有 → ホーム画面に追加」でアプリとして使えます。ローカル開発以外でのService WorkerにはHTTPSが必要です。`server.mjs` 自体はTLS終端を提供しません。

公開には `index.html`、`src/`、`public/`、`sw.js`、`manifest.webmanifest` をHTTPS対応の静的ホストに配置します。ホストのルートパスでの配置を想定しています。実端末でのインストール・OSごとの動作確認と公開作業は別途必要です。

## Windows・Chromebook・Android・iPadで共有

同じアカウントのタスクを共有する機能です。招待・複数ユーザー間の共同編集には対応していません。実際の同期には利用者所有のSupabaseプロジェクトが必要です。

1. Supabaseでプロジェクトを作成し、SQL Editorで [`supabase.sql`](./supabase.sql) を実行します。RLSで本人の認証IDの文書だけを読み書きできます。
2. AuthenticationのEmail / Passwordを有効にします。確認メールを使う場合は、Site URLを公開先に設定します。
3. アプリの「設定・データ同期」にProject URLとPublishable key（またはlegacy anon key）を入力して保存します。**service_role / secret keyは使用しないでください。** 公開用キーはブラウザーに保存され、アクセス保護はRLSが担います。
4. アカウントを作成して確認メールを開き、ログインします。既存アカウントでも構いません。
5. すべての端末で同じ公開URLを開き、同じProject URL・公開用キー・アカウントでログインします。「今すぐ同期」で成功を確認してください。

変更後・オンライン復帰・画面復帰・約1分ごとに同期します。即時リアルタイム同期ではありません。オフラインの変更は端末に保存され、復帰後に統合します。タスク単位・プロジェクト単位で更新日時の新しいものを採用します。同じタスクの同時編集は後の変更が優先されるので、端末の時計は自動設定を推奨します。バージョン比較付きの更新で、アップロード中の上書き競合を検出し再試行します。削除・アーカイブ・チェックリストの期間・進行度・列名も同期されます。以前のデータは引き継ぎ、新しいフィールドのないタスクは「順調・未アーカイブ・チェック項目は期間なし」として扱います。SQLの変更は不要です。

ログアウトしても端末内のタスクは残ります。共有端末ではログアウトだけではデータは消えないため、バックアップ後にブラウザーのサイトデータを削除してください。

画像を含むデータを1つの文書として同期します。大量の画像を扱うワークスペースには向きません。将来の大容量運用ではStorage等への分離を検討してください。APIエラー時も端末内のデータは利用できます。

## 検証

```sh
npm test
npm run check
npm run test:e2e -- --workers=2
```

E2EはChromiumでPCとモバイルの表示を確認し、必要なら開発サーバーを起動します。`/usr/bin/chromium` がなければ、`CHROMIUM_PATH` でインストール済みChromiumを指定してください。テストの対象は `test/taskly-model.test.mjs` と `test/taskly.spec.js` です。

同期のE2EはモックAPIによる認証・統合・更新競合の検証です。実Supabaseの認証、RLS、実端末間同期は、プロジェクトを接続した後の確認が必要です。実機のSafari・Android・Windows・ChromeOSでは未検証です。

## 構成

- `src/app.js`：画面と操作、画像圧縮
- `src/model.js`：データ形式、検証、日程計算、同期マージ
- `src/storage.js`：IndexedDBによる保存
- `src/sync.js`：Supabase認証・同期
- `sw.js`：アプリファイルのオフラインキャッシュ

端末内のデータベース名は `taskly-data`、クラウドテーブル名は `taskly_documents` です。
